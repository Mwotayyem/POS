# UI — Login (شاشة تسجيل الدخول)

> تصميم شاشة الدخول في **Smart ERP POS**. مبنية على **ASP.NET Core MVC + Bootstrap 5**، تدعم **RTL/العربية** أصلاً، و**التخصيص لكل مستأجر** (شعار/خلفية/ألوان) دون إعادة نشر. تلتزم بمنطق [05-Authentication.md](../05-Authentication.md) و[API/Authentication.md](../API/Authentication.md).

---

## 1) الهدف (Purpose)

نقطة الدخول الوحيدة للنظام. تُوثّق المستخدم، تحلّ المستأجر (Tenant Resolution)، وتُطبّق هوية المستأجر البصرية قبل المصادقة. يجب أن تكون سريعة، آمنة، وموثوقة على شاشات اللمس (Cashier).

---

## 2) حلّ المستأجر والتخصيص (Tenant Resolution & Branding)

| الطريقة | مثال | الأولوية |
|---------|------|:--------:|
| Subdomain | `acme.smartpos.app` | 1 |
| Path Slug | `smartpos.app/t/acme` | 2 |
| رأس مخصّص | `X-Tenant-Slug: acme` | 3 |

عند تحديد المستأجر، تُحمَّل هويته البصرية من `TenantSettings`:

| العنصر | المصدر | الافتراضي |
|--------|--------|-----------|
| الشعار | `TenantSettings.LogoUrl` | شعار المنصّة |
| اللون الأساسي | `TenantSettings.PrimaryColor` | `#2563EB` |
| الخلفية | `TenantSettings.Settings.loginBackground` | تدرّج افتراضي |
| اللغة/الاتجاه | `TenantSettings.Settings.locale` | `ar` / RTL |

```html
<!-- الألوان تُحقن كمتغيّرات CSS من إعدادات المستأجر -->
<style>
  :root {
    --brand-primary: @Model.PrimaryColor;   /* #2563EB */
    --brand-bg: url('@Model.LoginBackgroundUrl');
  }
</style>
```

## 4) الحقول (Fields)

| الحقل | النوع | إجباري | التحقق |
|-------|------|:------:|--------|
| البريد | `email` | نعم | صيغة بريد صحيحة |
| كلمة المرور | `password` مع زر إظهار 👁 | نعم | غير فارغة |
| الفرع | `select` (يُحمَّل بعد البريد) | لا | من فروع المستأجر |
| تذكّرني | `checkbox` | لا | يُطيل عمر الجلسة |

---

## 5) الأزرار (Buttons)

| الزر | الفعل | الملاحظة |
|------|------|----------|
| **تسجيل الدخول** | `POST /api/v1/auth/login` عبر AJAX | يُعطَّل ويُظهر spinner أثناء الطلب |
| **نسيت كلمة المرور؟** | يفتح modal → `forgot-password` | لا يكشف وجود البريد |
| **رمز التحقق (OTP)** | تدفّق `otp/send` → `otp/verify` | للمستأجرين المفعّل لديهم 2FA |
| **إظهار كلمة المرور** | toggle `type` | تحسين UX للمس |
| **تبديل اللغة** | ع / EN | يعكس الاتجاه RTL/LTR |

---

## 6) الأخطاء (Error Handling)

| الحالة | الرسالة | العرض |
|--------|---------|-------|
| بيانات خاطئة (401) | "البريد أو كلمة المرور غير صحيحة" | Alert أحمر أعلى النموذج |
| حساب مقفل (423) | "تم قفل الحساب مؤقتاً، حاول بعد X دقيقة" | Alert تحذيري |
| محاولات كثيرة (429) | "محاولات كثيرة، انتظر قليلاً" | تعطيل الزر + عدّاد |
| بريد غير مؤكّد (403) | "يرجى تأكيد بريدك أولاً" | رابط إعادة إرسال |
| خطأ شبكة | "تعذّر الاتصال، حاول مجدداً" | Toast |

> **مبدأ أمني:** لا نميّز بين "بريد غير موجود" و"كلمة خاطئة" — رسالة موحّدة تمنع Enumeration.

## 7) تدفّق الدخول (Login Flow)

```
[فتح الصفحة] → [حلّ المستأجر من subdomain] → [تحميل هوية المستأجر]
      ↓
[إدخال البريد + كلمة المرور] → [تسجيل الدخول]
      ↓
   POST /auth/login
      ↓
 ┌────────────┴────────────┐
 │ 2FA مفعّل؟             │
 ├── نعم → OTP → verify ──┤→ [استلام Access + Refresh Token]
 └── لا ──────────────────┘         ↓
                          [تخزين التوكن (HttpOnly cookie / secure storage)]
                                     ↓
                          [توجيه حسب الدور: Cashier→POS، Manager→Dashboard]
```

---

## 8) الأمان (Security)

1. **HTTPS إجباري** — لا دخول عبر HTTP.
2. Access Token في **HttpOnly + Secure cookie** (Web) أو تخزين آمن (POS terminal).
3. **CSRF Token** على نموذج MVC (`@Html.AntiForgeryToken()`).
4. **Rate Limiting** على `/auth/login` (5/دقيقة/IP).
5. **Lockout** بعد 5 محاولات فاشلة.
6. تعطيل autocomplete لكلمة المرور على الأجهزة المشتركة (POS).

## 10) الاستجابة والوصولية (Responsive & A11y)

- **Responsive:** البطاقة تتكيّف؛ على الجوال تملأ العرض. أزرار كبيرة (≥ 44px) للمس.
- **RTL:** الاتجاه يتبع `locale` المستأجر؛ Bootstrap RTL bundle.
- **A11y:** `aria-label` لكل حقل، تباين لوني كافٍ، دعم لوحة المفاتيح (Tab/Enter)، رسائل الخطأ مرتبطة بـ `aria-describedby`.
- زر الدخول قابل للتفعيل بـ **Enter** من أي حقل.
