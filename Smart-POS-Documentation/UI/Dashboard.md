# UI — Dashboard (لوحة التحكم)

> تصميم لوحة التحكم في **Smart ERP POS**. مبنية على **MVC + Bootstrap 5 + Chart.js + SignalR** للتحديث اللحظي. تعرض مؤشّرات الأداء (KPIs)، المخططات، والتنبيهات لكل مستأجر/فرع. تلتزم بـ [21-Dashboard.md](../21-Dashboard.md).

---

## 1) الهدف (Purpose)

نظرة تنفيذية لحظية على أداء المتجر: المبيعات، الأرباح، المخزون المنخفض، أفضل المنتجات، وحالة الشفتات. تتكيّف محتوياتها حسب **دور المستخدم** و**الفرع المحدَّد**.

---

## 2) الصلاحيات والسياق (Access & Context)

| الدور | ما يراه |
|-------|---------|
| Tenant Owner | كل الفروع (مجمّع + تفصيل لكل فرع) |
| Store Manager | فرعه فقط |
| Accountant | مؤشّرات مالية (بلا تفاصيل تشغيلية) |
| Cashier | لا يصل للوحة (يُوجَّه لـ POS) |

**شريط السياق العلوي:** منتقي الفرع (Owner فقط) + منتقي الفترة (اليوم/الأسبوع/الشهر/مخصّص).

## 4) بطاقات المؤشّرات (KPI Widgets)

| البطاقة | القيمة | المقارنة | المصدر |
|---------|--------|----------|--------|
| مبيعات اليوم | `Total` مجموع | ▲/▼ % مقابل أمس | `sp_SalesReport_Summary` |
| أرباح اليوم | `GrossProfit` | ▲/▼ % | تقرير المبيعات |
| عدد الفواتير | `InvoiceCount` | العدد | المبيعات |
| متوسط الفاتورة | `NetSales/Count` | القيمة | محسوب |

كل بطاقة: أيقونة ملوّنة + رقم كبير + سهم اتجاه (أخضر/أحمر) + نسبة التغيّر. تُحدَّث لحظياً عبر **SignalR** عند كل عملية بيع جديدة.

```javascript
// تحديث لحظي عبر SignalR
connection.on("SaleCompleted", (payload) => {
  updateKpi("todaySales", payload.runningTotal);
  salesLineChart.data.datasets[0].data.push(payload.amount);
  salesLineChart.update();
});
```

## 5) المخططات (Charts — Chart.js)

| المخطط | النوع | البيانات |
|--------|------|----------|
| مبيعات آخر 7 أيام | Line | مبيعات يومية (تعبئة تدرّجية) |
| المبيعات حسب التصنيف | Doughnut | نسبة كل تصنيف |
| المبيعات بالساعة | Bar | ذروة اليوم (تخطيط الكاشيرين) |
| المشتريات مقابل المبيعات | Grouped Bar | مقارنة شهرية |

- ألوان المخططات مشتقّة من `PrimaryColor` المستأجر + لوحة ثانوية متناسقة.
- Tooltips بالعملة المحلية (`CurrencyCode`) مع الفاصلة الصحيحة.
- خيار **تصدير PNG** لكل مخطط.

## 6) الجداول (Data Widgets)

| الجدول | الأعمدة | التفاعل |
|--------|---------|---------|
| أفضل 10 منتجات | المنتج، الكمية، الإيراد | نقر → صفحة المنتج |
| مخزون منخفض | المنتج، الرصيد، حدّ الطلب | نقر → إنشاء أمر شراء |
| آخر الفواتير | الرقم، المبلغ، الوقت | نقر → عرض الفاتورة |
| حالة الشفتات | الكاشير، الفتح، المبيعات | مباشر (Live) |

- صف "مخزون منخفض" يُبرز بلون تحذيري (`bg-warning-subtle`) عند `qtyOnHand ≤ reorderLevel`.

---

## 7) التحديث اللحظي (Real-Time via SignalR)

- **Hub:** `/hubs/dashboard` — المستخدم ينضم لمجموعة `tenant_{id}_store_{id}`.
- الأحداث المبثوثة: `SaleCompleted`, `StockLow`, `ShiftOpened`, `ShiftClosed`.
- التحديث تفاضلي (يحدّث القيمة المتأثّرة فقط، لا يعيد تحميل الصفحة).
- Fallback: Polling كل 60 ثانية إن فشل WebSocket.

---

## 8) الاستجابة (Responsive Design)

| الشاشة | السلوك |
|--------|--------|
| Desktop (≥1200px) | 4 بطاقات في صف، مخططان جنباً لجنب |
| Tablet (768–1199px) | بطاقتان في صف، المخططات فوق بعضها |
| Mobile (<768px) | بطاقة واحدة/صف، Sidebar ينهار لـ Offcanvas، جداول أفقية Scroll |

- Sidebar قابل للطيّ (collapse) لتوسيع مساحة العرض.

---

## 9) التخصيص لكل مستأجر (Tenant Customization)

- الألوان من `PrimaryColor` تُطبَّق على البطاقات والمخططات.
- الويدجت قابلة للإخفاء/الإظهار حسب `Business Type` (مثل: "تنبيه صلاحية قريبة" يظهر للصيدليات فقط).
- ترتيب الويدجت قابل للحفظ لكل مستخدم في `Settings` (Scope: User).

---

## 10) الأداء والأمان

- **الأداء:** استعلامات KPI عبر SP مجمّعة (انظر [StoredProcedures.md](../Database/StoredProcedures.md)) مع Covering Indexes؛ نتائج قابلة للتخزين المؤقت 30–60 ثانية (Redis).
- زمن تحميل مستهدف < 2s (p95).
- **الأمان:** كل استعلام مفلتر بـ `TenantId`/`StoreId`؛ Owner فقط يرى بيانات فروع أخرى. لا كشف أرقام فروع لا يملك صلاحيتها.
